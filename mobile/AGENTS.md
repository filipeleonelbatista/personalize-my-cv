This is an Expo/React Native mobile application (SDK 57). Prioritize mobile-first patterns, performance, and cross-platform compatibility.

## Expo has changed — do not trust your training data

Expo ships breaking changes every SDK release. APIs you remember are likely renamed, moved, or removed. Before writing any code that touches an Expo, EAS, or React Native API:

1. Read the major version of the `expo` package in `package.json` (currently 57).
2. Fetch the matching versioned docs: `https://docs.expo.dev/versions/v<major>.0.0/`
3. For anything else, fetch https://docs.expo.dev/llms.txt — an index of all Expo docs with corrections to common LLM misconceptions. Follow its links to the specific page you need; never answer from memory.

## Commands

```bash
npx expo install <package>  # ALWAYS use instead of npm add — resolves SDK-compatible versions
npx expo start              # start the dev server
npx tsc --noEmit            # typecheck
npx expo-doctor             # diagnose dependency and config issues
npx expo install --fix      # fix incompatible package versions
npm test -- --run           # vitest suite (run inside mobile/)
```

There is no eslint config in this project — `npx expo lint` does not apply. Verification is `tsc` + vitest + `expo-doctor`. `babel-preset-expo` must stay installed or Metro bundling fails.

npm quirk: this repo pins `.npmrc` with `legacy-peer-deps=true` because Expo 57 ships `react-dom@19.3.0` against pinned `react@19.2.3` — plain `npm i/rm` always fails with ERESOLVE without it. Never remove that line.

## Navigation & Routing

- Use **Expo Router** for all navigation. Routes live in `mobile/app/` — every file there is a screen, `_layout.tsx` files define navigators. Keep non-route code (components, hooks, utils) outside `mobile/app/`.
- Import `Link`, `router`, and `useLocalSearchParams` from `expo-router`.
- Docs: https://docs.expo.dev/router/introduction.md

## Styling

- NativeWind v4. Metro helper is `withNativeWind` (capital W) from `nativewind/metro`. Type setup lives in `nativewind-env.d.ts`.
- Theme toggle goes through `lib/theme.tsx` (`useTheme().setScheme`), never by touching `useColorScheme` directly in screens.
- No native Picker: option rows use `Pressable` (native Picker needs a dev build and breaks Expo Go).

## Storage & device APIs

- UI state in AsyncStorage (`lib/store.ts`, keys `pmcv:*`); Gemini key ONLY in `expo-secure-store` (`lib/secure-key.ts`).
- Classic filesystem API lives at `expo-file-system/legacy` (SDK 54+ moved it; the root import no longer has `documentDirectory`).
- PDF text extraction runs in a hidden WebView with vendored pdf.js (`assets/pdfjs/`, regenerated by `scripts/vendor-pdfjs.mjs`); file bytes travel as base64 because `file://` fetch is blocked. `PdfExtractorHost` must stay mounted in the root layout.
- PDF output via `expo-print` (HTML in `lib/cv-html.ts`); download to the device library via `expo-media-library` (permission first); share via `expo-sharing`.
- Offline guard lives in `lib/net.ts` (`ensureOnline()`) — every AI entry point must call it.

## Tests

- Vitest with native-module doubles via `resolve.alias` in `vitest.config.ts` (`tests/__mocks__/`). Never import `react-native` or Expo native modules in lib code covered by tests without adding an alias mock — the Flow syntax crashes vitest.
- Contract tests assert structure via file reads (routes exist, header cluster, no hardcoded UI strings outside `lib/messages/`). All 3 locales must share the exact keyset.
- Locale for lib code comes from `getLocale()` (runtime cache fed by the provider) — React Native has no `localStorage`.

## Building with EAS

Use EAS to build in the cloud (`eas build`, `eas submit`). Run EAS CLI as `npx eas-cli@latest <command>`. Login is interactive (`eas login`) — never invent or print credentials.
Docs: https://docs.expo.dev/eas/index.md

## Rules

- If `ios/` and `android/` directories do not exist, they are generated (Continuous Native Generation). Never create or edit them by hand — configure native behavior in `app.json` and config plugins.
- Splash screen goes through the `expo-splash-screen` config plugin — the top-level `splash` key in `app.json` is rejected by the SDK 57 schema.
- Never share code with `web/` — this project is self-contained by decision (see root `PROJECT.md`). Equivalent logic may be reimplemented, never imported.
- Prefer recommended Expo modules over third-party libraries, and check your available skills before adding dependencies. Docs: https://docs.expo.dev/versions/latest/index.md
